# Code Connect: every Figma component points at its code

Each GurtOS component in Figma maps to the kit component that builds it in `portal/` (Preact, `portal/src/kit/ui.tsx`,
`shell.tsx`, `wm.tsx`). There are 95 mappings: 23 components, 58 symbolic icons and 14 app icons.

## What works today, and what waits for a plan

Figma's Code Connect needs an Organization or Enterprise plan. The GurtOS file is in a student team, and the Figma
MCP's Code Connect tools answer "You need a Dev or Full seat on an Organization or Enterprise plan to use Code
Connect". So the mappings live in two places:

1. **In Figma, now (any plan).** Every mapped component's description ends with "Code (GurtOS kit):", a one-line
   usage example and the source file and line. Its documentation link opens that line on GitHub. Dev Mode shows both
   when you select an instance. `apply-to-figma.js` writes them and is safe to run again.
2. **As Code Connect templates, ready to publish.** `templates/` holds one parserless template (`.figma.ts`) per
   component, written to Figma's Code Connect skill: each Figma property maps to a real prop of the kit component,
   every variant value is mapped, and icons pass their name to the component that holds them (`metadata.props.name`).
   On an Organization or Enterprise plan, publish them with:

   ```sh
   cd docs/figma/code-connect
   FIGMA_ACCESS_TOKEN=<token with Code Connect write> npx -p @figma/code-connect figma connect publish --config figma.config.json
   ```

   or have an agent send `map.json` through the Figma MCP's `send_code_connect_mappings`. Dev Mode then shows the
   template's code, filled in from the selected instance (for example `<Button kind="destructive" large>Undo task</Button>`).

## Files

| File | What it is |
|---|---|
| `templates/*.figma.ts` | One template per component: Button, IconButton, Switch, Badge, Chip, TextField, Dropdown, Progress, Row (Row, SwitchRow, ComboRow or LinkRow by its Trailing variant), ToggleGroup, SidebarItem, StepItem, AppRow, AlertDialog, MenuItem, Toast, StatusPage, Notification, QuickToggle, TopBar, Dock, PhoneTabBar, WindowControls |
| `templates/icons/`, `templates/apps/` | Generated by `gen-icons.ts`: `<Icon name="..." />` and `<AppIcon id="..." />` for every icon component. Seven icons and three app icons are in Figma but not in the kit yet; their templates say so |
| `map.ts` → `map.json` | Reads every template's `url`, `source`, `component` and `example` lines and writes the list the Figma step uses, with GitHub links to the exact line |
| `apply-to-figma.js` | The plugin code that writes `map.json` into the Figma components (run with `MAP` set to `map.json`) |
| `figma.config.json` | Code Connect CLI config for the templates |

## Keeping it right

- After changing a kit component's props, update its template. After moving code, run `node docs/figma/code-connect/map.ts`
  and re-run the Figma step, so the links point at the new lines.
- Not mapped on purpose: the phone's status bar and Live Activities (drawn by iOS), the GNOME Shell surfaces of
  GurtOS Personal (built in `personal/shell/`, not in the kit), and the retired direction A components.
