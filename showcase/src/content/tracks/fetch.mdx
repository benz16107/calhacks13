## Why GurtOS, and what each part is for

**A safe body for ASI:One, on a computer you own.** A GurtOS Server box is always reachable: it answers from its
Agentverse mailbox with no open port, even when your laptop is shut. GurtOS Personal does the same on your own laptop.
Either way, the portal and the phone show every chat task live, and you can approve, undo or pause it from there.

## Evidence

**A chat, start to finish.** These replies are from a live run through ASI:One, shortened.

1. **Pair once.** The box's screen shows a six-digit code. The chat sends `pair 123456`. The box answers "Paired. This
   box now takes work from you here." Anyone else gets only the pairing step and cannot start, approve or undo
   anything.
2. **Ask for work.** "Fix the failing test in my project." The box starts a Droid task in its own copy of the `project`
   workspace, a small sample repo whose bill-splitting function loses a cent. The task has no network of its own and
   a 25 cent budget.
3. **The result comes back:** "Done: Fix the failing test in my project. ($0.05)", Droid's summary, the changed files,
   the diff, and a card with **Keep** and **Undo**.
4. **A pause for your OK.** "Check if the Hario V60 paper filters (size 02, 100 count) are back in stock." Droid
   searches the web through the box's Apify tool. A search counts $0.50, more than the budget, so the task stops and
   the chat gets a card: "Paused for your OK: Spend $0.50 on apify.run? Budget $0.25, spent $0.00." with **Approve**
   and **Deny**. After Approve: "Done: Check if the Hario V60 paper filters... ($0.57). The size 02 filters (100 count)
   are in stock on Hario's US store at $10.25..."
5. **Any time:** "status" lists your latest tasks with state and cost. "undo" takes back the last one.

## How it works

<Flow steps={frontmatter.flow} />

**Talking to ASI:One's planner.** The planner sends the agent a message and uses its first reply, so the box replies
within 40 seconds with the result, an approval card, or "still working" and the latest step. A later "status check"
from the planner gets the task's next news and never starts a new task. A card click comes back as JSON in a direct
chat, or in the planner's own words ("The user approved the card interaction..."); then it applies to the last card
shown in that chat session.

**Cards.** Approvals and results go out as `MetadataContent` in the
[ASI:One Interactive Cards](https://innovationlab.fetch.ai/resources/docs/interactive-cards/asi-interactive-cards)
format, `card_kind: "review"`, with **Approve** and **Deny** for a pause and **Keep** and **Undo** for a result.

**The chat agent has no powers the portal lacks.** `brain.py` uses only the box's HTTP API, the one the portal and the
phone use. It runs as `nobody`: it can use that API, but cannot read the vault or the workspaces. Tasks hold no keys
and have no network of their own; web work goes through box tools that run in the core.

**Reliability.** Replies wait in a durable outbox until they are sent, and a failed send is tried again. After a
restart or a power cut, the agent picks up from the box's action log where it stopped, and the box's tasks resume
too. If the agent process dies, the box starts it again within 5 seconds.

**Safety.** Only paired owners give work and answer cards. A code works once, and the box takes at most ten wrong
codes a minute from everyone together. Any spending above the task's budget waits for the owner's OK.

## Try it

**At our table.** The box's screen shows the ASI:One app with the agent's address and a pairing code. Open ASI:One,
find the agent `box`, send `pair <code>`, then ask "fix the failing test in my project". Approve the card when it
comes, then press Undo on the result.

**On your own box** (Ubuntu 24.04 with GurtOS installed):

1. Put `AGENTVERSE_API_KEY`, `ASI_ONE_API_KEY` and `FACTORY_API_KEY` (and optionally `APIFY_TOKEN`) in
   `/etc/box/vault.env`.
2. Turn the agent on:
   ```sh
   curl -X POST http://127.0.0.1:7700/t/fetch/agent -H 'content-type: application/json' -d '{"on": true}'
   ```
   The first time it installs uAgents into `/opt/box-fetch/venv`, about 30 seconds. It stays on across restarts.
3. Open `http://127.0.0.1:7700/t/fetch/` for the agent's address and the pairing code.
4. In ASI:One, find the agent by its address, open a chat, send `pair <code>`, then ask for work.

## Limits

- A card click relayed through ASI:One's planner arrives in the planner's words, without the selection, so the box
  applies it to the last card in that chat session.
- Droid may search the web more than once, and each search above the budget asks again.
- To reply into a chat session from a timer, `agent.py` sets a private uAgents field, so uAgents is pinned to 0.26.1.
- One team per box. Two boxes with the same seed would split one mailbox.
- Dorado's explorer stopped indexing new blocks, so payment receipts link to the raw transaction on Fetch's testnet API. All payments are test FET with no value.
- The screening rules catch the common shapes of an instruction. A novel one may get through the rules and the model check, but it still cannot make GurtOS do anything.
- The three TEST agents are ours, labelled TEST on Agentverse. They stand in for strangers so a hostile reply and payments both ways can be shown on cue.
