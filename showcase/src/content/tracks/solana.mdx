## Why it needs an operating system

On an ordinary computer, an agent that can pay holds the private key. It sits in an environment variable or a file that any process the agent starts can read, so one bad web page or one wrong model step can drain the wallet, and nothing records which piece of work spent what.

GurtOS puts each agent task in its own Linux user, with its own copy of the files and no keys. The wallet's key lives in a file only root can read, and only the box's own payment tool opens it. Each task has a budget, and a payment above it waits for the owner's tap on the phone. Solana makes the result checkable from outside: the memo on each payment names the task, and the log fingerprint lets anyone confirm the box's record still matches what it published.

On Ubuntu 24.04 with GurtOS installed:

1. Make a wallet: `node --experimental-strip-types tracks/wallet/keygen.ts | sudo sh -c 'cat >> /etc/box/vault.env'`. It prints the address.
2. Fund it at faucet.circle.com: USDC, Solana Devnet, 20 USDC. Payments need no SOL. The log fingerprint needs a little devnet SOL.

4. Find the two new transfers on your wallet's Explorer page.

<Details summary="How a payment is signed, and what the box refuses to sign">

1. The agent calls `wallet.quote` with a URL. The box, not the task, fetches it. The API answers `402 Payment Required` with a price and a payee.
2. The agent calls `wallet.pay` with that exact price. The box counts it against the task's budget and reserves it, so two payments at once cannot both slip through. Above the budget, the task waits for the owner on the portal or phone.
3. The box builds an SPL `TransferChecked` of devnet USDC to the payee's token account, adds the memo with the task id, and signs with the key from `/etc/box/vault.env`.
4. The facilitator (Coinbase's CDP facilitator, or x402.org without CDP keys) adds its signature as fee payer and submits it.
5. The box waits for confirmation, then writes the amount, payee, task and signature to the action log, labelled devnet test money.

**It refuses** any offer that is not devnet USDC, any amount other than the one quoted, any host not on the task's list, and redirects. Before signing it writes a durable mark, so a box that loses power mid-payment never pays twice.

**The fingerprint** (`tracks/wallet/audit.ts`). Once a day the box hashes its action log up to the latest entry and writes the entry count, that SHA-256 and the previous fingerprint's hash to Solana in a memo the wallet signs, so the chain shows which box wrote it. The verify route hashes the log's first N entries again and compares the result with the memo on chain.

</Details>

<Limits>

- Devnet only, by design. The network and the asset are fixed in `tracks/wallet/track.ts`. Mainnet needs real USDC and a review.
- The fingerprint shows a change made after it was written. A change made before it is not caught. On Oct 24 the 11 fingerprints come from several demo boxes sharing one wallet, so their entry numbers are not in order.
- The paid APIs are our own test APIs: $0.01 for a joke, $0.03 for a report, and a metered search of a box's published files.
- After a power cut in the middle of a payment, the call fails instead of checking the chain for whether it went through. The owner checks the wallet on Explorer.
- The box holds the key. A CDP Server Wallet would let Coinbase hold it; that mode is built but was not run live.

</Limits>
