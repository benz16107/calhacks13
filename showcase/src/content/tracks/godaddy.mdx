## One name for the whole product

One name for the whole product. GurtOS is the same word in the OS, the portal, the docs and the domain. gurtos.com is the docs, calhacks.gurtos.com is this showcase, and app.gurtos.com is the phone app. Every box that turns on remote access gets its own address, `<name>.box.gurtos.com` (for example `rosa.box.gurtos.com`), with its own Let's Encrypt certificate, and the encryption ends on the box itself.

**Not yet: the short domain.** gurtos.co is not registered yet. GoDaddy's command line says it is available from the registry at $8.99 for the first year, and the team will register it with MLH's code. The plan is the short domain for pairing: the QR on a box's screen would open `gurtos.co/p/<name>#<code>`, which forwards to the pairing page on app.gurtos.com. The one-time code sits after the `#`, and a browser never sends that part to a server, so no log at gurtos.co or app.gurtos.com could hold it. Everything else on gurtos.co would forward to gurtos.com. A shorter link also makes a smaller, easier-to-scan QR code (39 characters instead of 66). Until the domain resolves, nothing in the repo or in a box's QR code points at gurtos.co, and the redirect rules and the DNS commands are not on main yet.

The timing in the project's Figma stage log: the product was renamed from "Box" to GurtOS in every Figma file
between 9:27 and 9:41 PM PT on Friday, and the domain was registered at 9:29 PM PT, in the middle of that rename.

The name is one string everywhere, checked on main:

| Where | What it says |
|---|---|
| Boot screen and deck | The wordmark: "Gurt" in Instrument Sans SemiBold, "OS" in Regular, so it reads as Gurt plus OS |
| The installed OS | `/etc/os-release` has `NAME="GurtOS"`, `PRETTY_NAME="GurtOS Server <version>"`, `ID=gurtos` |
| The install discs | `gurtos-server-x86_64.iso` and `gurtos-personal-x86_64.iso` |
| Each box | The hostname `gurt-<id>`, from the box's own identity key, so two boxes never share a name |
| The portal | The menu bar, the phone and the page title read the name from one constant |
| The docs | `NAME` in `site/src/product.ts`; every page, title and OpenGraph image takes it from there |

**The docs stay hackathon-free.** The docs build runs a privacy scan (`site/scripts/privacy-check.mjs`) that fails
if any page mentions the event, a sponsor or Devpost, or names a private machine. Everything about the hackathon
lives on this subdomain instead.

## How it works

<Flow steps={frontmatter.flow} />

Both sites are static. Neither has a server that can reach a box: a box listens on its owner's own network, and
pairing a phone happens with a one-time code shown on the box's screen. So these two sites are never a way in. A box with remote access on is reached only at its own `<name>.box.gurtos.com` address, which ends TLS on the box and answers only paired phones.

## Try it

1. Open [gurtos.com](https://gurtos.com). The docs open with no sign-in.
2. Check who answers for the domain: `dig NS gurtos.com +short` prints the two `domaincontrol.com` nameservers.
3. Read the registry record: `curl -s https://rdap.verisign.com/com/v1/domain/gurtos.com`.
4. On a GurtOS box, `cat /etc/os-release` prints `NAME="GurtOS"`, and `hostname` prints `gurt-` and the box's id.

## Limits

- The domain has no email (no MX records) and no DNSSEC yet.
- A box is never reachable at gurtos.com. The name points at documentation and this write-up only. A box with remote access on has its own `<name>.box.gurtos.com` address.
- gurtos.co is not registered, so there are no short pairing links yet.
- The landing page is the docs site, not a Figma Sites page as first planned.
