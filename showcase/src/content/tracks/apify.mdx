## Why GurtOS, and what each part is for

**The problem.** A web agent today drives your logged-in browser with your accounts, reads booby-trapped pages, and
you cannot see what it spends. Existing systems were built for one person at a keyboard, so the agent holds everything
you hold.

**GurtOS runs Apify's robots from the agent's own space.** The agent never sees the Apify token (the broker holds
it), a page it reads is treated as untrusted data, and the run's cost counts against the task's budget and shows in the
portal and the phone. On a GurtOS Server box, schedules and webhooks start tasks while you are away. It is light (one
Node service, 4 GB of memory) and open source under Apache-2.0.

## How it works

<Flow steps={frontmatter.flow} />

| Tool | What it does | Actor | Cost the box counts |
|---|---|---|---|
| `apify.checkPrice` | Live price and stock of a product at Best Buy Canada, by SKU, link or search words | `apify/playwright-scraper` | 1 cent |
| `apify.findPlaces` | Places on Google Maps near a location | `compass/crawler-google-places` | 0.4 cents a place |
| `apify.run` | Any Actor from the Apify Store, with an input; returns its results | The agent's pick | Its spending cap, default $0.50 |

**Why these Actors.**

- **Playwright Scraper for Best Buy.** Best Buy Canada serves its product data as open JSON, with price and stock in
  one answer. The Actor opens it in a browser on Apify's servers and a small page function keeps only the useful
  fields. For a search it queues each hit's product page, because only that page says whether it is in stock. We
  first used Cheerio Scraper, which is lighter, but it needs full access to the Apify account, so Apify refused it
  until a person approves it, and approving it would let a hijacked agent send it its own page code through
  `apify.run`. Playwright Scraper runs page code with limited permissions.
- **Google Maps Scraper** (by Compass) for places: the most used Actor in the Store, about 45,000 users a month, $0.004
  a place on the free plan with no start fee. The tool turns every paid extra off and asks for only the ten fields it
  returns.
- **Any Actor** through `apify.run`, so an agent is not limited to what we wrapped. For other stores,
  `apify/e-commerce-scraping-tool` covers bestbuy.com, Walmart, Target and about 200 more.

**Why a hijacked agent cannot misuse it.**

- **The token is never in the task:** not in its files, environment or network. The tool refuses to return a result
  that contains it, and the merge gate checks the log for it.
- **An Actor never gets the token either.** Apify starts each run with its own short-lived token. Actors with limited
  permissions, Apify's default, reach only that run's storage. An Actor that wants full account access fails with a
  403 until a person approves it in Apify Console, and the API cannot approve it.
- **Spending is capped twice:** Apify holds a run to `maxTotalChargeUsd` and a 120-second timeout, and the box asks
  for an OK before any call above the task's budget.
- **Results are data.** A scraped page may carry instructions, but the agent's task still has no network and no
  secrets to act on them with.

**Left out on purpose.** Amazon refuses AI agents, so the box does not shop there. Apify's hosted MCP server would put
the token in the agent's own session; here the box's own MCP relay gives Droid the same kind of tools with the token
kept in the core.

## Try it

1. Sign up free at apify.com (the free plan includes $5 of usage a month) and copy the token from Settings, API &
   Integrations. A scoped token works: allow running Actors and reading their datasets.
2. On the box: `echo 'APIFY_TOKEN=apify_api_...' | sudo tee -a /etc/box/vault.env`. The file stays root only.
3. Start a task that lists the tool, for example with the tools `apify.checkPrice` and no hosts: "What does Best Buy
   Canada charge for AirPods Pro, and are they in stock?"
4. Or run the live test: `DEMO_LIVE=apify ./demo`.

## Limits

- `apify.checkPrice` covers Best Buy Canada only, with prices in CAD. bestbuy.com drops plain requests; the E-commerce
  Scraping Tool reaches it through Apify's unblocking proxy, through `apify.run`.
- Apify's synchronous run endpoint waits at most 300 seconds, so each tool sets its own Actor timeout below that: 90
  seconds for prices, 120 for places and other Actors.
- Apify's run endpoint takes no idempotency key. A call cut off by a power cut starts a new run when the task resumes.
  These tools only read the web, so the only cost is one more small run.
