## Stage log

The four stages Figma asks for, as submitted. Each is under 200 words. Minutes are the sum of the sessions in
`docs/stagelog.md` for that stage; every session there names its tool, its minutes, its rating, and how its output
reached the project.

**Ideation (FigJam and Figma Design, 32 minutes, 4 of 5).** Claude Code built the FigJam board through Figma's MCP
server: the architecture and the four demo moments with `generate_diagram`, and the 25 sponsor tracks grouped by the
slot each plugs into. When the first screens looked like a B2B dashboard, it collected 15 OS references from
official pages into a moodboard on the same board, then drew three OS directions (home-server OS, across-the-room
console, hardware OS) on the box screen and the phone. Ben picked the home-server OS. Output reached the project as
`docs/figma/refs/` and `docs/figma/directions/`. When the built screens still read as a SaaS product, a second round
collected 15 references from GNOME, elementary OS, macOS, Windows 11, Ubuntu, Synology DSM, umbrelOS and iOS, each
with one rule to take from it, into `docs/figma/refs/os-system/` and a new section of the board. Those rules became
the GurtOS design system in `docs/figma/system.md`.

**Prototyping (Figma Design and Figma Make, 6 minutes, 4 of 5).** Two flows wired between the real screens with
prototype reactions: an approval arriving on the phone, Approve, the task running again; and undo one task on the
box, with a confirm step. The same flows went into a Figma Make file as a small web page in the design's tokens,
tested in a browser first. Links are in `docs/figma.md`.

**Handoff (Figma's MCP server and exported frames, 19 minutes, 4 of 5).** Every color and size is a variable with
CSS code syntax, every screen and component is named, and `docs/figma.md` lists each screen's node ID and the API
data behind it. The portal thread reads them with `get_design_context`. The GNOME frames for GurtOS Personal went
the other way: native GTK and libadwaita widgets have no web code, so the desktop layer was built from the exported
frames and their notes. The indicator took the frames' "Needs you" and "Running" sections, the notification its
"Approve $8.00" button, and the review its Undo and Keep.

**Code generation (Figma's MCP server, 67 minutes, 4 of 5).** Claude Code read the screens with
`get_design_context` (box home, phone home, Notification Center, the task window) and adapted the React and
Tailwind reference into the portal's own Preact components and CSS, keeping Figma's variable names as CSS custom
properties so every token stays traceable. Assets came from the same responses: both wallpapers, and the glyphs,
which collapsed from 33 exports into one path set because Figma draws every size with the same 3 px stroke. Every
mockup value the box can't back up changed: progress bars became "working" bars, the daily limit became "on tools
and models", and Activity's spend bars are computed from the real log. The result reached the project as
`portal/`: one web app the box serves as its own kiosk screen, as the portal, and on a phone, checked against the
PNGs in `docs/figma/os/`. The Shopper app came first, from the approval card on screen g and the Paper tokens. Two
Figma frames have no web equivalent: Live Activities and the Dynamic Island.

### The same token in the design and the code

The design file's variables have CSS code syntax, so `get_design_context` returns code that already uses the
portal's names. The shipped CSS keeps them:

```css
/* portal/src/style.css, lines 17, 36 and 42, named after the Figma variables */
  --color-desktop-accent: #f2b544;
  --color-state-waiting-fg: #7f4c00; --color-state-waiting-bg: #f8ebd0;
  --radius-sm: 4px; --radius-md: 6px; --radius-window: 14px; --radius-widget: 24px;
```

**What changed between mockup and code, on purpose.** Values the box cannot back up were changed, not faked:
progress bars became "working" bars because the box does not know how many steps a task will take, Figma's "of a
$5.00 daily limit" became "on tools and models" because the box has no daily limit, and Activity's spend bars are
computed from the real action log.

## How it works

<Flow steps={frontmatter.flow} title="From FigJam to the running OS" />

Claude Code did the Figma work through Figma's MCP server: `generate_diagram` for the FigJam architecture,
`use_figma` for the boards, tokens, components, screens, prototype reactions and the deck, `upload_assets` for
the moodboard images, `send_code_to_figma` for the Make file, and `get_design_context` plus `download_assets` to
bring the screens back out as code. Ben made the calls a designer makes: which direction, what to cut, and when the
built screens still looked like a SaaS product.

The handoff is designed to be read by a machine. Every frame is named, auto layout is used throughout, components
carry data-named text properties, and `docs/figma.md` maps each screen's node ID to the API data behind it. The
portal is one Preact app the box serves itself, so the box screen, a laptop and a phone need one address and no
internet: the two fonts, Instrument Sans and IBM Plex Mono, are self-hosted.

## Try it

1. Open the [ideation board](https://www.figma.com/board/KvHiDv5HIJuGYOZDDkp8VG) and the
   [design file](https://www.figma.com/design/oppzH621OOOMA31rgLbxbM). No sign-in needed.
2. Run the prototypes above, or open them full size from the links.
3. With Figma's MCP server: `get_design_context` on file `oppzH621OOOMA31rgLbxbM`, node `23:84` (the box home) or
   `24:554` (the task window). The returned code uses the same `--color-*` names as `portal/src/style.css`.
4. Build the portal from the repo: `cd portal && npm ci && npm run build`, then compare it with
   `docs/figma/os/*.png`.

## Limits

- Live Activities and the Dynamic Island are drawn in Figma but have no web equivalent, because they belong to the
  phone's own OS.
- The Make prototype has no published URL, and its preview did not load signed out. The embedded prototype above
  is the Figma Design one.
- The GurtOS system v2 is design only so far. The portal will be rebuilt from it after Ben's review.
- The portal was checked against the Figma PNGs by eye, not with an automated visual diff.
- Weave was not used: the Figma account is not linked to it, so no Weave run happened.
