## Best Workflow: from idea to running code

The map below was drawn in FigJam. Claude Code works through Figma's MCP server: `generate_diagram` for the FigJam architecture, `use_figma` for boards, tokens, components, screens, prototype reactions and the deck, `send_code_to_figma` for the Make files, and `get_design_context` with `download_assets` to bring screens back out as code. Ben made the calls a designer makes: which direction, what to cut, and when the built screens still looked like a SaaS product.

<Shot src="track/figma/ecosystem-map.png" alt="A FigJam map of the whole ecosystem: Claude Code through the Figma MCP exports variables to a tokens export and drift check, writes 95 Code Connect mappings, and logs minutes to the stage log. The portal kit of Preact and CSS tokens feeds GurtOS Server, Business, the phone app, the docs and showcase, and Personal on GNOME. Screenshots return to an app-vs-Figma comparison." caption="How design and code stay tied: variables are exported and drift-checked, 95 components are mapped to the portal kit, and the built screens are photographed back next to their frames." />

1. **Ideation.** A FigJam board with the architecture, the four demo moments and the 25 sponsor tracks. Two rounds of OS research (15 references each) and three drawn directions. Ben picked the home-server OS.
2. **System.** The GurtOS design system: variables in Light and Dark, each with its CSS name, and components.
3. **Screens.** 64 v2 screens drawn only from the system, then Personal on GNOME, Business and the phone app.
4. **Prototype.** Four wired flows with 136 links, and the phone app in Figma Make.
5. **Handoff.** `get_design_context` returns reference code that already uses the token names.
6. **Code.** One Preact portal for the box screen, a laptop and a phone, and native GTK 4 and libadwaita windows for Personal.
7. **Check.** A script exports the variables and fails when the kit drifts; another puts each frame beside the running app with a difference score.

```css
/* portal/src/kit/kit.css: each line is a Figma variable of the same name */
  --color-accent-bg: #2f64a6;      /* accent/bg, Light */
  --color-accent-fg: #2a5c99;      /* accent/fg, Light */
  --color-accent-subtle: #dce6f3;  /* accent/subtle, Light */
  /* Dark: */ --color-accent-bg: #78a9e6; --color-accent-fg: #8db8ee; --color-accent-subtle: #2c4361;
```

## Most Creative: one design system for three editions and four devices

An operating system for agents has to feel like an operating system people trust, not another dashboard, and it has to reach people on a server screen, a GNOME desktop, a company's approval flow and a phone. We drew all of it from one system and used more of Figma than a mockup needs:

- **Edition as a variable.** A collection with Server, Personal and Business modes drives the edition prototype: one component, three modes, and a machine switcher on the phone that changes the mode.
- **Code Connect templates.** 95 components are mapped to the Preact kit in `docs/figma/code-connect/`. Publishing to Figma needs an Organization plan, so they are not published; each component's Dev Mode description holds its kit code and a link to the source line instead.
- **A generative plugin** that finds fills and strokes not bound to a GurtOS colour variable, names the nearest token, and binds exact Light-mode matches. Run on the file, the Business and landing pages came back fully bound.
- **A shader fill** for the wallpaper, "GurtOS night hills". It builds and deploys; nobody has seen it render yet, because the MCP cannot draw a custom shader, so the stage log rates it 3 of 5.
- **A landing page and a Community playbook** designed in Figma. The landing page is published on Figma Sites. The Community file is linked from it, and Figma blocks automated checks of that page, so it was not verified here.

## Why this needs an operating system

On an ordinary system a design stops at the mockup: the app is built once and drifts. GurtOS is built from the design on purpose, and the OS gives the design something real to show: every screen shows the computer's own state (its tasks, its approvals, its log), so a frame has nothing to fake.

For the last push it researched every Figma product into `docs/figma-products.md` and drew one FigJam map of the whole ecosystem.

**Prototyping (Figma Design and Figma Make, 61 minutes, 4 of 5).** The first round wired two flows between the real screens: an approval arriving on the phone, and undoing one task on the box with a confirm step. After the redesign, Claude Code wired four flows across the 64 v2 screens with 136 prototype links: all 12 setup steps, approving a spend on the phone (the approval arrives on the lock screen after 1.2 s), undoing one task on the box through to an undone state with a toast, and the desktop with Notification Center, Control Center and every Settings page. **Handoff (Figma Design and Figma's MCP server, 67 minutes, 4 of 5).** Two handoffs. The first (4 minutes) made the design file ready for code: every frame named, auto layout throughout, and every color, size and motion value a variable with its CSS name as code syntax, so `get_design_context` emits the names the portal uses. `docs/figma.md` lists each screen's node ID and the API data behind it. After the redesign, `docs/figma/os-v2/README.md` does the same for every v2 screen, matched to the core's setup, settings, apps and vault routes, and the screens reached main in six batches so the portal thread could build each one while the next was drawn. The second (15 minutes) took the Personal (GNOME) frames to the Personal thread as exported PNGs with notes, not as web code, because Personal is native GTK and libadwaita. Each frame's sections became a widget: the indicator menu's "Needs you" and "Running", the notification's actions, the Ask an Agent dialog's access group. `docs/figma/system.md` holds the rules, including guidelines for app makers. The last push tied design to code: every component's Dev Mode description now holds its kit code and source link (publishing Code Connect needs an Organization plan), and a script exports the variables and fails when the kit's tokens drift.
