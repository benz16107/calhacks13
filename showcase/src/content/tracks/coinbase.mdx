## Summary

**Who it's for.** People who leave AI agents running unattended on a home machine and want them to buy what a job
needs, such as an API call, without handing an agent a private key or a card.

**What it does.** Agents on the box pay for HTTP APIs that answer `402 Payment Required`, using x402. The box holds
the wallet in its vault and a task only ever sees results. Each task has a budget: a payment that fits goes through,
and one above it pauses the task until the owner approves it on the portal or phone, while other tasks keep running.
Every payment goes into the box's action log with its amount, payee, task and Solana transaction, and counts toward
the task's cost.

**Coinbase tools.**

- The x402 v2 TypeScript SDK: `@x402/fetch` and `@x402/core` to pay, `@x402/svm` for Solana, `@x402/express` for the
  test API that charges.
- Coinbase's CDP facilitator, through `createCdpFacilitatorClient` in `@coinbase/cdp-sdk/x402`, signed in with the
  box's CDP Secret API Key. It checks each payment, pays the Solana network fee and submits the transaction.
- The x402.org facilitator, Coinbase's public testnet one, as the fallback when the vault has no CDP keys.
- Not yet: CDP wallets (see Limits).

## How it works

<Flow steps={frontmatter.flow} />

**Controls.**

- **The key stays in the core.** It lives in `/etc/box/vault.env`, readable by root only. Only `wallet.pay` can read
  it, inside the box's own process. A task runs as its own Linux user with no way to read the vault.
- **The CDP key stays with the test API.** It is the seller's key: only `seller.ts` reads it, and no box tool
  declares it, so no task or tool can get it from the vault.
- **Budget, then the owner.** The broker counts each payment toward the task's budget and reserves it before the call
  runs. Above the budget, the task waits for an answer on the portal or phone. Denied means nothing is paid.
- **Exactly the agreed price.** `wallet.pay` names the amount, which is what the budget check and the owner saw. If
  the API asks for anything else, it pays nothing.
- **Only devnet USDC.** It pays only the `exact` scheme on Solana devnet in devnet USDC. The x402 client also refuses
  any single payment over $1, its default.
- **Only the task's hosts.** The wallet reaches only hosts on the task's list, by the same rule as the task's
  network, and refuses redirects. A task cannot point it at the box's own API.
- **Never twice.** Before paying, the wallet writes a durable mark for that call. If the box loses power mid-payment,
  the resumed call refuses to pay again instead of guessing.

## Try it

1. **Make a wallet** on a box. This prints the vault line, and the address on stderr:
   ```sh
   node --experimental-strip-types tracks/wallet/keygen.ts | sudo sh -c 'cat >> /etc/box/vault.env; chmod 600 /etc/box/vault.env'
   ```
2. **Fund it with devnet USDC** at faucet.circle.com: keep USDC, choose Solana Devnet, paste the address, press Send
   20 USDC. The wallet needs no SOL, because the facilitator pays the fees.
3. **Add CDP keys** for Coinbase's facilitator: in the CDP Portal, create a Secret API Key and add `CDP_API_KEY_ID`
   and `CDP_API_KEY_SECRET` to the vault. Without them the test API settles through x402.org instead.
4. **Run it:** `DEMO_LIVE=wallet ./demo` from the repo root. It ships the checkout to a test VM and runs every step,
   with real devnet payments for this track.
5. **Or by hand:** start the test API (`node --experimental-strip-types tracks/wallet/seller.ts`, port 4021), then
   start a Droid task with the tools `wallet.quote` and `wallet.pay`, the host `api.localhost:4021`, a 2 cent budget
   and the prompt "Buy one joke with the box wallet and write it to joke.md." The README has the exact command.

## Limits

- Devnet only, by design. Mainnet needs a different network and asset in `track.ts`, real USDC and a review.
- The box holds the wallet's key itself. A CDP wallet would keep the key with Coinbase so no private key is on the box
  at all; that needs a CDP wallet secret.
- The approval question comes from the core: "Spend $0.03 on wallet.pay? Budget $0.02, spent $0.01." It does not
  name the payee or URL yet. The quote step just before it, in the same task's log, does.
- `GET` only. APIs that want a `POST` body are not supported yet.
- After a power cut in the middle of a payment, the call fails rather than checking the chain for whether the payment
  went through. The owner checks the wallet on the explorer.
- API responses are cut at 20 KB.

## Builder feedback

Kept while building, Oct 23, with `@x402/core`, `@x402/fetch`, `@x402/svm` and `@x402/express` 2.28.0 and
`@coinbase/cdp-sdk` 1.60.0. The full notes are in
[FEEDBACK.md](https://github.com/benz16107/calhacks13/blob/main/tracks/wallet/FEEDBACK.md).

**What worked well.** The first devnet payment settled on the first try, about 15 minutes in, and took about 1.5 s
from the 402 to the 200. Swapping the x402.org facilitator for the CDP facilitator was one line. On Solana the
facilitator pays the fee, so an agent wallet needs only USDC, which saved us from a devnet SOL faucet that answered
429 all evening. `registerPolicy` was the right hook to pay only the devnet USDC offer at the approved price.

**Friction.** The four that cost the most time come first.

1. Two Solana versions in one install: `@x402/svm` 2.28.0 pulls `@solana/*` 6.10 while its token programs want
   `@solana/kit` ^5. We had to pin kit 5.5.1 by trial. About 30 minutes.
2. A payee without a USDC account fails with HTTP 402 and an empty body; the cause is only in a base64 header. About
   20 minutes. Asks: name the cause, and say in the seller quickstart that a new `payTo` needs a token account.
3. No idempotency key for payments, so a box that dies between settle and receipt would pay again on resume. We
   wrote our own durable mark. About 20 minutes.
4. `@coinbase/cdp-sdk/x402` imports `@x402/evm` on load even for Solana, failing with `ERR_MODULE_NOT_FOUND`. About
   5 minutes.
5. Two CDP facilitator helpers, one stale: `@coinbase/x402` 2.1.0 still shows up in docs and pulls about 82 MB.
6. `HTTPFacilitatorClient` prints `[x402] extension responses: {}` on every payment with CDP, with no way to turn it
   off.
7. `decodePaymentResponseHeader` on a missing header throws a bare JSON `SyntaxError`.
8. The CDP facilitator's `/supported` answers 401 without keys, so we could not check Solana devnet support before
   signing up.
9. "Pay exactly this much" needs a custom policy; a built-in `expectedAmount` option would be harder to get wrong.
10. Docs link to both `coinbase/x402` and `x402-foundation/x402`, and it took a moment to trust they are one project.
