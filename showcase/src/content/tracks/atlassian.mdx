## How it works

<Flow steps={frontmatter.flow} />

**Into Jira.** The box feeds the track every event in its append-only log, in order, and saves its place, so it
survives restarts and power cuts. Agent output only ever goes into Atlassian Document Format text nodes, so a task
cannot inject markup, links or mentions into Jira. Status follows the task: queued is To Do, running is In
Progress, waiting for an OK is In Review, and done, failed or rolled back is Done. It is safe to repeat: a crash
between creating an issue and saving its key finds the issue by label instead of making a second one.

**Out of Jira.** The panel's resolver runs in Atlassian's cloud. It reads the issue's `box.task` property as the
signed-in user (so the task id comes from Jira, never from the browser), asks Jira whether that user may edit the
issue, and only then calls the box with the shared secret, passing the user's name for the log. The box checks the
secret in constant time and checks that the approval belongs to that task. From the internet, the box forwards
only its Jira routes and one read-only status route; the rest of its API is a 404.

| Forge or Atlassian piece | Used for |
|---|---|
| `jira:issuePanel` (UI Kit, native render) | The Box agent task panel on `BOX` issues |
| `@forge/resolver` | `load`, `answer`, `rollback` |
| `jira:entityProperty` | JQL fields `boxState`, `boxCost`, `boxBlocked`, `boxPending`, `boxSource` |
| `api.asUser().requestJira` | Reads the property, the user's permissions and name, with the user's own access |
| `fetch` with `permissions.external.fetch.backend` | The one call out, to the box |
| Encrypted variable `BOX_SECRET` | The shared secret |
| Jira REST v3, from the box | `issue`, `properties`, `transitions`, `comment`, `search/jql` |

## Try it

1. Put `ATLASSIAN_SITE`, `ATLASSIAN_EMAIL`, `ATLASSIAN_API_TOKEN` and `JIRA_BOX_SECRET` in the box's vault,
   `/etc/box/vault.env`.
2. Turn syncing on: `echo '{"project":"BOX"}' > /var/lib/box/jira/config.json`.
3. Give the box public HTTPS for `/t/jira/*` only (the README has the Caddy block).
4. From `tracks/jira/forge/`: `forge variables set --encrypt BOX_SECRET <secret>`, `forge deploy`, `forge install`.
5. Start any task on the box. Its issue appears in `BOX`; open the panel and try Approve and Roll back.

The full steps are in the [track README](https://github.com/benz16107/calhacks13/tree/main/tracks/jira) and the
docs guide [Connect Jira](https://gurtos.com/guides/connect-jira/).

## Limits

- Roll back undoes the task's **file changes**. It cannot recall something a task already sent out through a tool,
  such as a payment. Those show in the issue so a person can follow up.
- One shared secret guards the box's three Jira routes. Forge Remote's signed invocation tokens would let the box
  check each call came from this app and this user; that is the next step.
- The box writes to Jira with one person's API token, so its comments show that person as the author.
- The panel polls the box every 4 seconds while it is open.
- Issue descriptions keep the last 40 log entries and the first 8,000 characters of the diff. The panel and the
  box's log have the rest.
