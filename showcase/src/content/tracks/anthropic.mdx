## Why GurtOS, and what each part is for

**The community:** solo developers who leave agents running unattended at home. **What GurtOS does for them:** the
agent keeps real access to a copy of your files and never holds your keys, and you can see and stop it from the portal
or your phone, on a computer you own. Almost all of it comes from the OS, not from any one agent.

## How it works

<Flow steps={frontmatter.flow} />

The box service is the only part that runs as root. It starts each task as a hardened systemd unit under a new
user (uid 30000 to 39999): it sees only its own processes, has a private `/tmp`, can write only its copy and its
home, cannot reach D-Bus, and gets at most 2 GB of memory. An nftables rule lets task users reach nothing but the
box's proxy, and the proxy lets a task reach only the hosts in its spec. Droid's calls to Factory go through the
same proxy, which swaps the placeholder key for the real one, so the real key never enters the task.

Undo works because each task writes into its own overlayfs layer. When the task finishes, its layer goes on top of
the workspace. Undo takes that one layer out of the stack, and the base files are never written.

## Try it

1. On an Ubuntu 24.04 machine set aside for agents: `sudo core/install.sh`.
2. Add one model key, an Anthropic API key or a Factory API key, in setup or Settings (it goes into the root-only vault).
3. Open `http://<box>:7700/` and start a task, or:

   ```sh
   curl -s 127.0.0.1:7700/api/tasks -H 'content-type: application/json' \
     -d '{"title": "Tidy my notes", "prompt": "Fix the spelling in notes.md and change nothing else."}'
   ```

4. Open the task to see Claude's steps and diff. Press Undo to take its changes back.

The docs walk through it: [install on Ubuntu](https://gurtos.com/get-started/install-on-ubuntu/), then
[your first task](https://gurtos.com/get-started/first-task/).

## Limits

These are the places the box can still go wrong. The full list is the
[threat model](https://gurtos.com/security/threat-model/).

- **A shared kernel.** Tasks are separated by Linux users, systemd and overlayfs, not virtual machines. A kernel
  exploit inside a task escapes all of them.
- **Only the box's own screen gets in without a token.** From anywhere else, every API call needs a paired phone's
  token, and SpacetimeDB listens on loopback and takes answers only from connections the box vouched for. Anyone
  with a shell on the box itself, or a stolen phone token, can still answer approvals; revoke the phone in Settings.
- **The model provider sees what the agent sees.** Prompts, files and tool results go to the model through Factory.
- **An allowed host gets whatever the task sends it.** Allow narrow hosts.
- **Undo cannot recall what already left**, such as a payment or a request to an allowed host.
- **Model spending does not pause a task.** It counts toward the budget check for the next paid tool call.
- **An agent writes its own questions.** Read a question from `box_ask` as a claim. Budget approvals are written by
  the core from the tool's declared cost.
