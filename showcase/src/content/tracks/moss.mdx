## The attack a memory has to survive

A memory that agents write to is an attack surface. Here a page the agent was summarising carries an instruction to remember a standing rule.

<Compare labels={['Memory on an ordinary computer', 'Memory on GurtOS Personal']}>
<div slot="a">

The agent writes the rule into its notes. The next task, and every one after it, reads the rule as something you said. Nothing records where it came from, and nothing asks you.

</div>
<div slot="b">

The task reached the web, so it counts as untrusted. Its proposed memory is held until you answer. The question names the page, you press Deny, and the denial is logged. Later tasks with the same permissions are never handed it.

</div>
</Compare>

## What it remembers, and how you ask

You can search by what is in a photo, not what it is called. A photo named `IMG_2041.jpg` comes back for "whiteboard" because a vision model described it when it arrived.

<Shot src="track/moss/find-search.png" alt="The Find page: a search for whiteboard returns one photo, photos/IMG_2041.jpg, a whiteboard with a Sprint plan diagram, described by gemma4." caption="A search for whiteboard. This is the offline demo path: the description is one gemma4 wrote earlier (recorded), and a word index stands in for Moss. The photo is one of four we rendered ourselves, not a personal photo." size="narrow" />

- **Say it once, every app follows.** A preference such as "Never buy from Corner Market" is handed to every task in every app before it starts. The test shows the Shopper's task and the wallet's task each handed the same sentence.
- **Talk to your computer.** In GurtOS Personal, press Super+Alt+Space and ask out loud. The answer comes as a notification and a local voice. A spoken yes approves only a request that spends nothing, signed as the voice of the owner, and the audio is deleted after it is read.
- **Forget.** The Forget button on any result removes a memory, a task note, a photo's description or a file from the index and, when the computer keeps one, from Moss's cloud copy. The log keeps the id, never the content.

## Why this needs an operating system

Moss finds the relevant notes by meaning, in milliseconds. Everything that decides what an agent may see or remember is GurtOS's own rule, and none of it depends on Moss: it holds the same when Moss is out of reach and a word match answers.

<Steps title="Try it" time="About two minutes on a GurtOS computer.">

1. Open Find from the app grid. A new computer has four test photos in a `photos` workspace.
2. Search "whiteboard". With no model set, photos are found by file name until you set one; set `FIND_OLLAMA_URL` in Settings to describe them with a model on your own machine.
3. Open the Memory view, type a preference and press Remember. Start any task and look for the step "Handed over 1 memory block".
4. Or check from a shell: `curl -s '127.0.0.1:7700/t/find/search?q=whiteboard&kind=photo'`.
5. Run the memory attack yourself on a test VM: `DEMO_ONLY=find ./demo`.

</Steps>

<Details summary="How memory reaches an agent, and the three places poisoning is blocked">

**Handed over before a task starts.** For every new task, GurtOS asks Moss for the owner's preferences and the few notes from past tasks that match the task's prompt, and adds them to the end of a Droid task's prompt. The task log gets one step, "Handed over N memory blocks", with the text. An agent can also call `find.recall`.

**Each agent sees only what its permissions allow.** A note carries the workspace, tools and hosts of the task it came from. A new task is handed it only if its own permissions cover all of those. A lesson from the Shopper's task never reaches a task with no Shopper tool. A stranger's task, from the public Mana app or an ASI:One stranger, is handed nothing, cannot call `find.remember`, and its own note is never indexed.

**Poisoning is blocked in three places.**

1. A task that could reach the outside (any host, or any tool but Find's own) is untrusted: its note carries a red badge and no agent is handed it. The owner can trust it.
2. An agent can only propose a memory. From an untrusted task, and for any preference, the owner must approve first through the one approval path (top bar, phone, desktop). A denial is logged as blocked and stored nowhere.
3. Only the owner states a preference directly.

**Which model describes a photo.** One function sends the photo to any OpenAI-compatible chat API. The computer tries models in order and the first that answers wins, and a failing model is skipped for 5 minutes. The prompt asks for the kind of thing first, then details and readable text, then 8 keywords.

**A CPU-only machine.** Measured on a 4 vCPU, 8 GB x86 VM with no GPU: `qwen3-vl:2b-instruct` is right on all four test photos and reads the text on the receipt and the whiteboard, at 22 to 37 s a photo once warm and 90 to 125 s for a new photo, with 5.1 GB of memory at peak. A first import of many photos is a slow background job. On a Mac with a GPU, gemma4 takes 1.1 to 2.8 s a photo.

</Details>

<Limits>

- **Photos leave the computer only if you choose.** Pressing Describe with Claude sends the photos to Factory, where Claude runs. Pointing the computer at a model on another machine sends them there. Only text goes to Moss's cloud copy, and that text includes the descriptions a vision model wrote about your photos.
- **The cloud copy is opt-in and one computer only.** Moss's project is over its usage limit, so the cloud half of Forget is untested. Search never needs the cloud.
- **Voice has not been tried through a real microphone**, and with no network at first boot the speech model is not downloaded, so the feature stays off.
- **Any task given `find.search` can search every workspace**, not only its own. A photo with text in it can carry that text into an agent's context as data.
- **Only the first 2,000 characters** of a text file are indexed.
- **A CPU-only computer describes a photo in minutes.**
- **The screenshots use test data:** four rendered photos, recorded descriptions and a scripted agent. No personal photos.
- We did not enter the social post example.

</Limits>
