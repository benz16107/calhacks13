## How it works

<Flow steps={frontmatter.flow} />

**The session.** `droid.ts` runs inside the task as the task's user. It calls `createSession` with the task's copy as
its working folder, `claude-sonnet-4-6`, `AutonomyLevel.High` and one MCP server, the box relay. High autonomy is
safe here because the box, not Droid, sets the limits: the permission handler proceeds, and the OS refuses what the
task may not do.

**Tools without keys.** `mcp.ts` is a stdio MCP server that Droid starts inside the task. It lists the box tools the
task may use (for example `apify__run` for `apify.run`) plus `box_ask`, and passes every call to the task's broker
socket. The tool runs in the box service with the vault, and only its result comes back. A call above the budget
returns "pending" until a person answers, so Droid keeps working and calls again.

**Questions.** Droid's `askUserHandler` turns each question into a box approval, keyed by a hash of the question, so
a retry reuses the same approval.

**Power cuts.** The Droid session id is saved in the log as the first step. After a restart, `droid.ts` calls
`resumeSession` with it and tells Droid: "The box restarted while you were working on this. Check what is already done
in the files, then finish." Tool calls already answered return their logged result, so nothing is paid twice.

**Cost.** Droid's result message carries token usage. The worker posts it to the broker, and the core prices it at
the model's list rates (`core/pricing.ts`), writing a `cost` event with the model and a token breakdown.

## Try it

1. Install the box on Ubuntu 24.04 (`sudo core/install.sh`) and put `FACTORY_API_KEY` in `/etc/box/vault.env`.
2. Start a Droid task. Droid is the default worker. The `project` workspace is a small repo with one failing test,
   made by the Fetch.ai track at boot:

   ```sh
   curl -s 127.0.0.1:7700/api/tasks -H 'content-type: application/json' -d '{
     "title": "Fix the failing test", "workspace": "project", "budgetCents": 25,
     "prompt": "Run the tests with node --test, find why one fails, and fix the code."}'
   ```

3. Watch its steps: `curl -s 127.0.0.1:7700/api/tasks/<id>`, or open the task in the portal.
4. Cut the power mid-task (on a test VM, `sudo reboot -f`). When the box is back, it resumes the task, and
   `droid.ts` picks up the same Droid session from the id it logged.

## Limits

- **Model spending does not pause a task.** It counts toward the budget for the next paid tool call, but Droid's own
  model use never stops it for an OK.
- **Droid gives up on a tool call after about 3 minutes.** The broker waits up to 150 seconds, then answers "pending"
  so Droid calls again. A task can wait hours for an OK this way, at the cost of repeated calls.
- **One worker model per box.** `BOX_MODEL` sets it for all tasks; a task cannot pick its own yet.
- **Droid's tool steps are cut to 200 characters** of input in the log. The diff and the worker log have the rest.
