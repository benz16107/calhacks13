## Why this needs an operating system

<Compare labels={["An ordinary computer", "GurtOS with Elastic"]}>
<div slot="a">

- Several agents, several tools, several log files in several places.
- Root, or an agent running as you, can edit or delete them.
- A week later you cannot say what changed, what it cost or why a job failed.
- An investigating AI that can also act is one more thing to trust.

</div>
<div slot="b">

- One append-only action log written by the OS, one entry per action, each hashed to the one before.
- Elastic keeps a copy written with a key that can only create documents.
- Ask in plain words, as yourself, and the answer cannot say more than your role may see.
- Elastic never holds the power to act. The agent leaves a request, and your phone gets the approval.

</div>
</Compare>

## The record root cannot rewrite

Someone with root can edit one entry and then recompute every hash after it, so the box's own chain looks clean. That is the gap Elastic closes.

1. The core writes each log entry with the SHA-256 of the line before it (`core/log.ts`). Edit, remove or reorder an entry and every link after it breaks.
2. Each entry also streams to Elastic with a key that can only create documents. No update, no delete, no overwrite.
3. Every ten minutes the box compares its log file with Elastic's hashes and writes the answer into the log, so a failed check is stored where it cannot be taken back.
4. The agent's `box.verify_log` tool reads the results for every box, and flags a box that has gone silent.

The live demo planted an edit and the agent named entries 466 to 474. A rewrite of every hash after the edit was still named. Overwrite, update and delete on Elastic's copy returned 403. **What it does not catch:** an entry changed in the seconds before Elastic has it, and a fully taken-over box that stops sending or lies about its own check. For that case, `node tracks/elastic/agent.ts verify log.jsonl <machine id>` checks a copy of a log without asking the box.

## From a finding to your phone

<Steps title="The path an alert takes" time="Alerts run every minute in Kibana.">

1. Four ES|QL rules watch the log: a task that read a page then tried to reach somewhere else, a task that went for a secret, a task spending $5 or more in 15 minutes, and a blocked destination no agent has tried before.
2. Each match leaves one row in `box-requests`. Elastic cannot reach the box. The box pulls its own requests.
3. The box turns the row into a task whose only step is to ask the owner, through the normal approval. The phone gets the push, and the answer is logged with who gave it.
4. The agent can also ask to undo a task (`box.request_undo`). If the owner approves, the box undoes it. The agent says "I asked", never "I undid".

</Steps>

The four rules are Kibana alerting rules, not Security detection rules, because a Serverless Elasticsearch project does not include those. Only undo is requestable. Pause and stop are not, because undo is the one task control the box gives an app.

<Steps title="Try it yourself" time="About 15 minutes with your own Elastic Serverless project.">

1. The Kibana project in the screenshots needs a sign-in to the project's Elastic account, so judges cannot open it. To reproduce it, create an Elasticsearch Serverless project and an admin API key.
2. On your own machine: `export KIBANA_URL=... ELASTIC_URL=... ELASTIC_API_KEY=...` then `node tracks/elastic/agent.ts install`. It creates the indexes, tools, workflow, alert rules, dashboard and agent.
3. Ask it: `node tracks/elastic/agent.ts ask "Why did the job routine fail?"`
4. Or run the offline part, which plants the edit and checks the chain with no Elastic account: `./demo`. The live part is `DEMO_LIVE=elastic ./demo`.

</Steps>

<Limits title="What is not covered">

- **An entry can be changed in the seconds before Elastic has it.** After that it cannot.
- **A fully taken-over box can stop sending, or lie about its own check.** The agent flags a box that goes silent, and `agent.ts verify` checks a copy of a log without asking the box.
- **Root can still change the log file on the box.** It is caught, not prevented.
- **Elastic's keys for people are made by hand.** A role change in GurtOS needs a new key.
- **Only undo is requestable.** Pause and stop are not.
- **The Ask GurtOS page** is not in the merge gate, and no screenshot of it is shown.
- **Kibana's Security detection rules are not in a Serverless Elasticsearch project,** so the alerts are alerting rules.
- **The Elastic trial ends about Oct 30, 2026.** After that the project goes away and the agent can no longer be asked.
- **The screenshots are Kibana's UI from Oct 24,** asked about demo runs. A signed-in Kibana is the only place to see them live.

</Limits>
